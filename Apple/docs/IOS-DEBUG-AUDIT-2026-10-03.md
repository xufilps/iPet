# iOS 首版排查记录 — 2026-10-03 / v0.2.0

基线 e065036a，实施范围见[排查计划](plans/IOS-DEBUG-AUDIT.md)。这次检查补强 iOS 首版的自动验证，没有新增养成规则、存档版本或自主移动。

## 发现与修复

| 问题 | 复现与依据 | 修复 |
| --- | --- | --- |
| 未识别库存在背包中消失 | 合法 JSONv9 的 `inventory = ["unresolved.item":4]` 可加载；原 `inventoryItems.compactMap` 过滤没有定义的 ID，界面显示空背包。数量始终仍在存档中 | 显示 ID、数量及“数据已保留，当前版本无法使用”；不允许使用，不删除数据 |
| 背包搜索无结果误报为空 | 已有库存时搜索不匹配，原空态文案仍为“背包空空的” | 只有真实无库存时显示空背包，过滤无结果显示“没有匹配物品” |
| 宿主应用测试未完全隔离 | 原模型用例使用临时目录，但应用入口仍创建默认模型；进入后台或自动保存可能写普通模拟器沙盒 | Debug TestAction 和 UI 测试启动显式传入隔离标记，创建独立临时目录和偏好；Release 不包含该分支。回归测试先确认目录隔离，再执行操作并比较普通存档原字节 |

独立审查发现首次隔离实现缺少显式 `DEBUG` 编译条件，已在 iOS Debug 配置补齐，Release 不定义该条件；工程生成器和生成工程一致。此问题属于本轮实现过程，不能作为基线已存在的正式版缺陷。检查保留了工作区原有的七个编辑器 SDK 标记，不将这些本地改动混入修复提交。

## 自动检查

共享 Swift 408 项（核心303 / 渲染99 / 输入6）、Python28项；iOS 模型由8项增至13项，新增未知库存、宿主隔离、损坏主档恢复备份、重启后活动暂停、进食结束恢复活动及离开角色页关闭消息的组合覆盖。未来版本原文件、资源缺失不建档、写入失败冻结与重试不补算、前后台时间基准、购买使用保存及预览不发奖仍有回归用例。

新增3条真实界面自动流程：

- 养宠“更多→休息→起床→摸头→投喂→饮水”，活动“文案→暂停→继续→停止”，确认烧烤禁用，返回主屏再激活，横屏进入设置。
- 商店“ab钙奶→购买放入背包”，背包“库存1→使用→库存0且使用禁用”，设置“预览消息→出现文字→关闭”。
- 等待窗口方向改变后，iPhone左右横屏/竖屏、iPad左右横屏/倒置竖屏/竖屏下滚动到预览、确认文字、关闭，并保留整屏截图。工程补齐四方向声明，解决测试工具的方向支持警告；iPhone倒置竖屏不列入该设备的操作证据。

界面测试使用 XCUITest 向模拟器应用投递操作，并断言可达按钮和实际库存变化；不是仅检查模型接口。新用例中曾把正常的前台工作推进误判为预览奖励、把横屏需要滚动的设置按钮误判为缺失，已纠正测试假设。验证脚本运行时修改测试参数造成一次收尾失败，不能将该轮算作完整通过；后续完整脚本已通过；最终提交前按同一份代码再作收尾验证。
