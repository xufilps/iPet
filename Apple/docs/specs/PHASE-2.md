# 阶段2设计规格：养成、活动与经济闭环

版本：设计稿v1 / 2026-10-01；状态：范围及详细规格已获用户确认，实施计划待审阅及执行方式选择，尚未进入实现。目标版本为iPet v0.2.0，保存格式目标为v2；当前应用仍是v0.1.0 / JSON v1。原版基线固定为 `1a06c5981330564bab05a098d2d7969a4b119dd3`，实机检查按用户决定暂缓，不作为本轮启动阻塞条件，也不标记通过。

## 目标与范围

从当前免费投喂的基础桌宠，推进到可持续的“活动→收益→购买→使用→状态变化→保存/恢复”循环。工作、学习、娱乐与物品数值使用原内置配置和原公式，不用自拟参数替换；窗口和面板按macOS习惯重建。先实现可靠核心，再接入资源/界面，最后验证整个闭环。各部分是同一阶段的依赖切片，不独立宣称阶段完成。

本阶段纳入内置13项活动：文案、烧烤、清屏、直播、修屏幕；学习、研究、学书法、学画画；玩游戏、删错误、跳绳、玩水。保留等级锁定、原时长、消耗、活动收益、完成奖金和必要的平衡修正。物品纳入food.lps、moredrink.lps、drug.lps、gift.lps共118条配置记录；转换时校验名称/ID唯一性，不能将记录数直接当成最终可购买数量。timelimit.lps的4条时限物品不纳入本阶段，避免在未实现日期/可用期规则时提供错误商品。

本阶段提供原物品图片、工作/学习/娱乐入口、金币与等级/经验/好感显示、商店、库存、当前活动进度和结束反馈、疾病限制及药品使用。自动购买、物品收藏、自定义/倍率活动、任务套餐、排程、联机赠送、第三方数据MOD、C#插件、Steam成就、完整统计、说话随机池、爬墙、多角色和iOS界面继续留在后续阶段。通用Item/Toy/Mail/Tool行为涉及代码处理器，不以食物库存实现代替其兼容。

## 核心与数据边界

继续保持PetCore纯Swift、不依赖AppKit/UIKit/SpriteKit。扩充PetState的金币、库存、重复食用到期时间和可选活动会话；现有字段/派生等级与状态判断保留。新增ActivityDefinition、ItemDefinition、PetCatalog、ActivitySession和命令结果模型；活动规则/食物规则分别放入聚焦的文件，避免把全部处理塞进PetEngine单个switch。

PetEngine保持单执行器所有权。增加开始/停止/继续活动、购买使用、买入库存、使用库存命令；返回明确成功/拒绝原因、实际收益或消耗和渲染事件。状态修改由核心完成，SpriteKit只播放动作/物品图像，SwiftUI不能自行扣金币或修改库存。目录清单在AppModel中加载校验后注入引擎，核心测试可注入小型目录。

保留现有单调时钟用于活跃时长，另外注入墙钟用于原版重复食用的到期时间，两者不能混用。随机源继续可注入，固定测试核对调用次序和分支；不宣称当前Swift随机算法产生与.NET相同种子的同一序列。

构建前扩展资源工具，将所需LPS转成版本化玩法JSON及图片映射。原始定义与平衡后的有效定义可追溯，ID使用内置来源和原名称稳定生成，不以排序索引、译名或随机UUID作为存档键。重复ID、非法数字、缺必需字段明确失败；输出保持UTF-8和确定顺序，并沿用内容相同不重写。来源哈希纳入清单。运行时不依赖LinePutScript，也不宣称通用LPS/MOD兼容。

## 活动规则与生命周期

开始活动需满足原LevelLimit，Ill时拒绝；选择同一正在进行活动等同手动停止。切换活动先结束旧会话，不发旧活动完成奖金，然后启动新会话，避免叠加收益。开始活动退出休息，记录活动ID、经过的活跃秒数、累计已入账收益和状态。休息命令先手动结束活动，再切换休息。

逻辑默认每15秒推进TimePass=0.05，按原顺序释放储存值、处理活动分支，再执行公共经验/心情/健康规则。工作分支：先计算饱腹/饮水需求；体力足够时承担30%需求并提高效率；低饱腹/饮水路径的额外体力扣减、25/60阈值和随机健康加成按源码次序处理。收益为max(0, t×MoneyBase×(2×efficiency−0.5))，Work入金币，Study/Play入经验，并累加会话GetCount。娱乐用原Feeling符号处理心情并更新互动基准；工作/学习沿用freedrop计算，不额外套一遍日常消耗。

原WorkTimer完成判断为经过时间严格大于配置Time，按这个边界测试；到期仅一次追加累计收益×FinishBonus，然后结束。手动停止、切换、休息和生病停止保留已经入账的收益，不扣回，也不发完成奖金。达到Ill后停止活动，先执行该步原规则再按原检查顺序结束；不能只凭health固定数值跳过CalMode。

原UI活动计时使用DateTime，iPet沿用无离线养成的产品边界：经过时间采用活跃单调时间，系统睡眠/退出不推进活动或收益。隐藏只暂停渲染，应用仍运行则活动继续。每次恢复重建计时基准；大于现有30秒的调度断层继续不追补。退出时保存进行中会话，加载后以“已暂停”显示，用户明确继续，剩余时长和已入账值保留。这是平台适配，必须更新差异矩阵，不宣称与原墙钟计时等价。

拖动期间暂停自主移动但不暂停逻辑活动计时。抚摸/拖动可播放临时反馈，结束后回到活动动画，不默默取消会话；食物/饮料/药品也不默默结束活动，使用反馈后恢复活动，若实际状态变为Ill则走状态失败停止。动画结果不能驱动经济结算。

## 物品、购买与疾病

保留原物品类别Food/Meal/Snack/Drink/Functional/Drug/Gift，显示原名称、描述、单价和有正有负的属性；经验、好感、健康和储存值不得因“看起来不合理”抹掉负值。永久目录包含元数据，按需加载图片；物品图片查找遵循原Image或Name映射及原回退。无法映射时明确显示占位与诊断，不能把emoji当成已还原原图。

提供“购买并使用”作为贴近原更好买的入口，以及“买入背包”作为原生库存适配入口。每次购买核对数量、有效ID和价格；本阶段单次1件，连续操作分别记录。低价且Exp<1000物品允许赊账，金币可负；对Price≥1000或Exp≥1000物品，沿用原Price≥当前Money时拒绝的边界，包括余额刚好相等也拒绝，界面提前说明。该特殊边界不擅自改为通常的余额不足判断。库存购买沿用同一价格策略，不触发食用效果/衰减，使用时消耗1件并应用效果；0库存、无效ID或拒绝购买不改变状态。

使用物品时h=max(0,(原到期时间−墙钟now)/3600)，礼品buff=max(0.5,1−h²×0.01)，其余buff=max(0.5,1−h²×0.02)。EatFood(buff)按原顺序对所有属性乘buff，体力/饱腹/饮水一半即时、一半入储存；更新h+=max(0.5,min(4,2−(Likability+Feeling/2)/5))，新到期=now+h小时。到期时间用UTC保存；墙钟退出期间流逝可减轻吃腻，这是原版物品冷却行为，不是离线扣减养成；改系统时间时仅用上述非负h公式，不把墙钟用于活动收益。

Ill时禁止新活动、活动中变Ill自动结束；药品和普通物品仍可使用，休息继续按原公式恢复。保留免费救急药“太阳系”：Exp−180、Strength−100、Likability−4、Health+50及其重复食用衰减，不新增“免费治疗且无代价”。不引入原版没有的独立疾病种类或自拟治疗成功率。

现有免费面包/饮料在v0.2移出正常养成主入口和菜单，避免绕过商店与药品的经济循环；旧存档已获得的状态不回滚。开发测试夹具仍可使用旧参数，用户恢复困境靠原免费救急药和休息。README明确这项行为变化。

## 存档v2与恢复

保持当前Application Support/VPetApple路径；首次加载v1先按旧模型完整校验，再在内存升级。保留名字、所有属性、经验/好感、储存值和resting；一次性补1000金币、空库存/食用历史、无活动会话。新宠物也按原1000金币初始化。旧原生版从未记录经济历史，补初始金币是明确的迁移适配，不宣称恢复旧收益；不会反复发放启动资金。

第一次写v2前创建独立、不可覆盖的v1原文件备份（文件名含UUID），包括可恢复的有效v1备份来源，并在提示中给出文件位置。正常previous备份轮换继续保留，不以其代替迁移前备份。原文件备份创建失败则禁止升级写入并提示；新v2校验成功后才原子写主文件。未来主/备份版本仍拒绝覆盖，损坏文件仍保留并尝试有效备份。

v2新增字段均要求有限数值；金币允许负，绝对值≤1e12；正/负储存值均允许且绝对值≤10000，避免救急药的负储存值被误判为损坏。库存数量为整数0–1000000，0项序列化时可省略；活动ID、elapsedSeconds和GetCount校验且无NaN/无穷，已入账收益与完成奖金不能重复结算。目录存在的会话超出其时长也只能在合法继续流程结算一次，不借重启重复发奖金。

保存携带玩法目录版本；无法识别的未来目录版本阻止写入。未知物品ID但目录版本可识别时保留数量/冷却原值、显示不可用项，不静默丢弃；未知活动ID恢复为不可继续的暂停会话，提示并允许无奖金结束。上述上限为原生数据安全边界，须在行为对照记录，不宣称原版没有上限。

关键购买、使用、活动开始/结束、手动暂停和升级完成立即请求保存，60秒自动保存、睡眠和退出保存继续保留。保存失败需显示具体错误，不显示已保存；可用状态继续在内存中，不能反复重新执行经济命令。回滚旧程序先退出并备份整个目录，再将独立v1备份复制为主文件，同时把v2主/previous移到保留目录；原生v1不能读取v2，严禁覆盖删除新版数据来回滚。

## 原生界面与动画

设置窗口扩为状态/活动/商店/背包/设置五个页面，保留显示隐藏、位置、大小与移动偏好及许可入口。状态页显示属性、金币、等级/经验和好感；活动页按三类列活动、等级锁定、消耗与收益类型、时长、开始/继续/停止和当前进度。商店可搜索和按类别筛选，物品显示价格、原图片、正负属性、当前食用倍率及两种购买操作；背包显示数量与使用按钮。拒绝操作在原页面提示原因，不依赖仅写控制台。

菜单栏保留休息、显示/隐藏、位置重置、退出，增加打开活动/商店/背包入口；窗口仍只在用户主动打开面板时激活。不重做桌宠穿透/焦点机制，不把新功能构建通过当成实机验收。

资源层为13项活动Graph建立显式映射，至少提供各活动可用的确定开始/循环/结束变体；资源确实缺阶段时在清单标明，不造帧。状态缺失沿用已记录回退并输出诊断；首批需确认文案、学习、玩游戏三个低等级入口有对应动画，不以待机代替并宣称活动动画完成。保持按帧加载/缓存限制，不预加载新增全目录。进食动画把原物品图片注入已有食物图层轨迹，Drink与其余graph映射按原配置选择。频繁打断后恢复活动动画，但不触发旧完成回调或重复发钱。
