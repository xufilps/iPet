# 阶段6A：iOS 原生应用首版设计

日期：2026-10-03。基线：iPet `1cefd697`。状态：设计待审阅，尚未实现 iOS 应用。此前的 iOS 证据仅为共享模块 Simulator 编译，不能视为应用或真机验收。

## 目标与明确边界

交付最低支持 iOS 26 / iPadOS 26 的应用内养宠版本，使用最新已安装稳定 Xcode SDK 的原生 Liquid Glass 界面和交互动效，复用当前内置萝莉斯、养成公式、活动与物品规则及版本9存档模型。2026-10-03本机工具链为Xcode 27.0 / Simulator SDK 27.0；SDK版本与最低部署版本分别记录，不将iOS 27模拟器验证宣称为iOS 26运行验证。角色固定在页面展示区域；不创建自主移动调度器，不移动展示区域，不提供爬墙、屏幕边缘躲藏或桌面悬浮窗口。活动动画中角色自身的动作继续播放；“固定”不等于冻结动画。

界面以简体中文为主，适配 iPhone 与 iPad、安全区域和系统字号。首版形成“互动→活动收益→购买→背包使用→属性变化→本地保存”的闭环。不接多角色、数据型 MOD、petloader、云存档、联机、Steam、C# 插件、AI、语音、小组件、通知或后台持续养成；不把 macOS 键盘宏、全局快捷键、跟随工具栏、桌面区域和窗口设置移入 iOS。

## 方案与取舍

采用现有 Xcode 工程新增 `iPet-iOS` 应用目标：SwiftUI 页面、SpriteKit 展示、独立 iOS 应用模型，依赖 PetCore 与 PetRendering，不依赖 PetMacInput。工程生成脚本保持可重复生成，macOS 目标及名称保持原样。相较复制桌面窗口流程，这能让触摸与生命周期保持清晰；相较另建重复核心，能够继续共用已经验证的规则与存档保护。

首版使用现有转换后的资源清单与内置动作，继续按需加载及48MiB纹理缓存限制，不预加载全部5257帧。资源体积仍较大，首版不声称已经达到发行体积或移动设备性能目标；资源包裁剪和压缩另列优化，不能以删除活动所需变体假装等价。iOS 图标用现有像素风母图重新导出独立 iOS AppIcon，填满系统图标画布，不直接使用有外部留白的 macOS 图标版式。

## Liquid Glass 与动效

优先采用原生 TabView、NavigationStack、toolbar、Menu、sheet 和系统玻璃按钮样式，让导航和操作层继承当前系统的 Liquid Glass 外观。角色舞台、状态正文和商品列表保持清晰内容层；玻璃用于浮动互动控件和导航，不把所有内容卡片叠成透明玻璃。

舞台的投喂/休息等自定义浮动控件通过 `glassEffect` 实现材质，同组控件置于 `GlassEffectContainer`。展开/收起的控件通过稳定的 `glassEffectID` 与匹配几何过渡保持连续形变；使用系统按钮的按压反馈和原生页面/详情转场。动效不能改变角色舞台位置，也不能触发重复养成事务。遵循“减少动态效果”“降低透明度”和较大文字设置；系统原生适配优先，必要时采用更明确的背景与弱化过渡，避免运动或透明度影响操作辨识。

实现与评审依据：[Apple：Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)、[Apple：Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)。当前共享Package的iOS 17声明与历史构建证据只描述旧基线；实施时同步提升Package平台声明、应用部署目标和共享模块验证命令至iOS 26，macOS最低版本14保持不变。不维护iOS 17—25兼容分支。

## 页面与操作

1. **养宠首页**：固定角色舞台、名字与等级、体力/饱腹/口渴/心情/健康、金币与当前活动。角色透明区域无互动；把触摸点转换为场景坐标，复用原摸头/身体区域及对应动画。提供免费食物、饮水、休息/起床入口，展示食物贴图。忙碌状态的互动遵循已有规则，页面明确反馈操作结果，不暗中移动角色。
2. **活动**：工作、学习、娱乐分组，复用13项活动定义与等级限制；显示当前进度、收益及开始/停止/暂停/继续。活动循环使用现有阶段变体，手动停止播放结束阶段；活动状态和动画状态均由应用模型协调，渲染层不修改养成值。
3. **商店与背包**：复用118项内置物品定义与实际图片，支持搜索、购买入包/立即使用、库存数量与使用结果。购买失败不扣款，库存使用保留原参数快照规则。自动定价默认与当前 macOS 一致，不复制价格公式。
4. **设置与说明**：本地消息开关、字号与播放参数、资源来源/授权和存档状态。消息呈现在应用内部，保留字素播放及长度限制；预览不结算养成奖励。桌面内/外置消息窗口与鼠标穿透选项不适用于 iOS。首版暂不迁移完整排程编辑、套餐管理、统计明细、旧LPS导入和键盘宏；这些是界面迁移缺口，共享核心能力不能冒充可用入口。

页面可按屏幕尺寸采用底部标签与弹出详情，不要求把 macOS 设置窗口压缩成手机长表单。角色舞台尺寸由布局计算，位置变化仅为窗口/旋转的布局重排，不属于自主移动。

## 数据与生命周期

存档位于 iOS 应用沙盒 Application Support 独立目录，使用现有 PetSaveStore 的版本9 JSON、原子写入与有效备份、损坏文件保留、未来版本保护。与 macOS 不共享存储位置，不自动导入或同步。加载错误应显示可理解的原因并禁止覆盖受保护存档；不能静默创建新宠物覆盖旧文件。

前台活跃时推进规则，每60秒、关键互动/经济操作后以及离开活跃状态时保存。离开活跃状态停止规则计时和动画推进，恢复时重置核心/渲染/消息计时，不补算后台、退出或系统挂起期间的养成变化。保留用户手动暂停状态；恢复已加载活动依照现有存档保护路径保持暂停，提供明确“继续”活动入口。生命周期不自动触发补收益、套餐续费或其它经济命令。写入失败显示错误；不得把系统不保证执行的终止回调作为唯一保存机制。

首版前台计时协调放在独立可验证组件中，主线程应用模型负责UI和场景；保存用单一串行所有者，避免重复计时器及并发读写。页面切换不建立第二个核心实例，不重复计时、不重复奖励。

## 文件范围与顺序

新增 `Apple/Apps/iOS/` 应用入口、模型、固定角色视图和原生页面；新增 iOS 生命周期相关测试、独立 iOS 图标目录及构建说明。按需要向共享层加入最小的可测生命周期协调接口；不得因 iOS 改变原养成公式、存档版本或桌面行为。修改 create_project.py 接入目标/共享scheme/资源与签名配置，修改仓库验证脚本纳入新目标和生成一致性。

实施先做应用目标与资源启动，再完成固定舞台/触摸和前后台保存，随后接活动与经济界面、本地消息和设置，最后汇总构建与验收证据。每步有Git检查点；不以目录存在或编译成功代替可用界面。

## 验证、风险与交付

- 核心回归继续运行现有规则测试；增加生命周期计时、后台不推进、重复激活不增加计时器、恢复手动暂停及存档错误不覆盖的验证。
- macOS 现有构建与测试继续通过；iOS 应用分别构建 iPhone/iPad Simulator，并实际启动、检查资源加载及关键操作。Simulator 证据不当作真机证据。
- 校验应用与共享模块最低部署版本均为26；当前可用运行时只有iOS 27，iOS 26运行验证须取得对应Simulator runtime或设备后单列补验，不以编译目标替代运行证据。检查Liquid Glass按钮、控件形变、原生sheet转场以及减少动态效果/降低透明度的可用性。
- 核对固定角色位置、触摸区域缩放、活动打断/循环/停止、物品贴图和买用闭环；前后台再进入不重复奖励。检查大字号、小屏与横竖屏可操作性。

交付应用工程、Simulator运行证据、功能差异表、构建/真机安装步骤与交接说明。回滚通过本阶段Git提交恢复工程与代码；正式存档格式不变，回滚不删除沙盒存档。iOS包体与设备内存是明确风险，最终压力验证仍按用户安排最后进行。
