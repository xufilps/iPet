# 行为对照 — 2026-10-01 / v0.1.0

对照基线 `1a06c598`，核心来源为 `GameSave.cs` 的 EatFood、StoreTake、CalMode 及属性 setter，`MainLogic.cs` 的 FunctionSpend 和默认 15 秒 EventTimer，`MainDisplay.cs` 的头部/身体抚摸入口。

| 行为 | Swift 首版 |
| --- | --- |
| 默认养成 | 每 15 秒推进 TimePass=0.05，保留饱腹/饮水、体力、健康、心情、经验和好感公式及运算顺序 |
| 低饱腹/饮水/心情 | 保留 setter 的溢出伤害、心情对健康/好感的影响与 0–100 截断 |
| 状态 | 保留 CalMode 的健康、心情、好感阈值和边界比较 |
| 投喂 | 一半体力/食物/饮料立即增加，一半缓慢释放；保留 StoreTake 将不足1的尾数丢弃的行为 |
| 抚摸 | 体力≥10且心情<100时体力-2、心情+1；其他状态仍播放动画 |
| 休息 | 保留原公式，包括饮水≥25的分支使后续≥75分支不可达；不擅自修正原逻辑 |
| 随机健康 | 保留原 Next(1,3) 的1或2；Next(0,1) 恒为0，不误移植为0或1随机 |
| 经验下降 | 等级可下降，历史好感可能短暂超过当前等级上限；存档允许原规则产生的合法历史值 |
| 时间 | 已查养成定时器和主存档加载路径未见离线补算；首版不新增离线消耗。暂停恢复重建时钟，长调度间隔不补算 |
| 互动空闲时间 | 用活跃逻辑时间计算，排除退出、睡眠和暂停的时间，这是生命周期适配 |
| 基础食物 | 免费面包/饮料使用明确的新参数，分别饱腹/饮水+30并有小量体力、心情和健康恢复；不声称与原商店等价 |
| 养成以外 | 不迁移工作、购物、疾病治疗、各类统计、插件事件和完整随机互动池 |

动画使用原1000×1000 PNG，按500×500逻辑画布绘制；触摸区使用 vup.lps 的头部/身体矩形。逐帧时长取文件名末尾毫秒字段，按帧序号自然排序；每动作/状态/阶段选择一个确定变体。首版共选用27个动作状态组合，并非原作全部动画。

Eat/Drink 按 `(图层名, mode)` 解析前景/背景，缺省饮料前景使用原 normal 共用图层。食物层运动轨迹保留，但图像用面包/牛奶 emoji 表示，属于原生首版适配。开始、循环、结束阶段按清单播放；摸头等一次性动作播放完后回待机，提起、行走和休息持续循环，结束请求进入结束阶段。动作打断直接替换时间线，防止旧动作回调污染新动作。

缺少对应状态时依次使用同动作 normal、同动作其他可用状态、对应状态待机、normal 待机，并输出诊断；身体动画原资源缺 normal，采用可用 happy 变体。纹理按帧懒加载，缓存估算上限48 MiB，当前节点与SpriteKit/GPU本身开销额外计算，不能将缓存上限当作进程RSS上限。

原C#源码现已从当前树移除，公式来源可通过 [差异矩阵的固定版本链接](UPSTREAM_COMPARISON.md) 或保留的Git历史查阅；本轮清理不改变上述养成规则。
